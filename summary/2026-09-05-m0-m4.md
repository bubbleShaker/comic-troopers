# M0〜M4 完了サマリ（2026-09-05）

スマホ縦持ちで1分だけ遊べるコミック調 3D シューターが、**タイトル → 60秒のラン → リザルト → リトライ**まで
一通り遊べる状態になった。

▶ https://bubbleshaker.github.io/comic-troopers/

遊び方は、左半分ドラッグで移動、右半分スワイプでダッシュ、射撃は自動ロックオン。
撃破するとコンボが伸びて倍率が上がり、被弾するとコンボが折れて減点される。即死は無い。

## コードの構成

```
src/
  core/     ゲームロジック（three.js に依存しない / Node でテストできる）
    config.ts    バランス数値を1か所に集約
    types.ts     Vec2 と幾何ヘルパ
    rng.ts       シード付き乱数（決定性を保ったまま湧きに乱数を使う）
    entities.ts  Player / Enemy / Bullet / World / WorldEvent の型
    player.ts    自機の移動・ダッシュ
    spawner.ts   ウェーブと湧き
    combat.ts    ロックオン・射撃・当たり判定
    score.ts     スコアとコンボ
    world.ts     フェーズ管理と1フレームの統括
  render/   three.js の描画（core の状態を読むだけ）
  input/    バーチャルスティックとスワイプ
  ui/       HUD・タイトル・リザルト（素の DOM）
tools/
  shot.mjs  スマホ相当のスクリーンショット取得（開発補助）
```

テストは 59 件。`core` が three.js に依存しないので、ブラウザ無しで当たり判定もスコアも検証できる。

## 効いた判断

### 1. core と render を分けた

`core` は three.js を import しない。おかげで「弾が低フレームレートで敵をすり抜ける」「撃破が二重に数えられる」
といったバグを、ブラウザを開かずにテストで固定できた。

### 2. 出来事を `world.events` に積む

撃破・被弾は core が「起きたこと」として記録するだけで、オノマトペや画面シェイクは render 側が
それを読んで決める。演出を足しても core が汚れない。

### 3. 縦持ちの視界を実測してからバランスを決めた

縦画面は水平方向に約 22m しか見えない。最初は射程 22m・フィールド半径 26m で作っていたため、
**画面外の敵を自動で撃っている**状態になっていた。スクリーンショットで実測し、射程 11m・半径 20m に直した。

### 4. 「放置が最適解」をテストで塞いだ

敵1発耐久では自動射撃が湧きに勝ってしまい、何もしないのが最善という状態だった。
2発耐久にして終盤の湧きが撃破速度を上回るようにし、次のテストで意図を固定した。

```
放置プレイでは終盤に囲まれて被弾する
```

難易度調整でここが赤くなったら、設計意図が壊れたサイン。

## つまずいた点

- **ヘッドレスの `--virtual-time-budget` では requestAnimationFrame が十分に回らない**。
  敵が湧く前の画面しか撮れず「敵が出ていない」と誤診しかけた。実時間で待つ `tools/shot.mjs` を用意して解決。
- **`main.ts` を書き直した際に `stage.render()` を落とし、3D が真っ黒になった**。
  HUD だけ動くので原因が見えづらかった。`renderer.info.render.calls` が 0 だったことから特定。
- **`CanvasTexture` の `colorSpace` 未指定**で地面が白飛びしていた。sRGB を Linear として扱われるため。
